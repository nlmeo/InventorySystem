# 测试容器交互验收方案（2026-10-23）

## 当前实现边界

本轮已加入 `AINV_TestContainer`、容器交互接口和玩家控制器的交互会话骨架：玩家追踪到容器后按主交互键，控制器取得容器的 `UINV_InventoryComponent` 并广播打开请求；再次对同一容器交互会关闭会话。容器默认交互距离为 250 uu，支持启用开关和距离拒绝。

当前已完成玩家拥有的双栏 UI 生命周期和运行时网格绑定；双栏跨组件拖放、网络拒绝恢复和蓝图样式接线按完整流程继续验收。完整步骤见 [双栏容器完整测试流程](双栏容器完整测试流程_2026-10-23.md)。

容器来源 UI 蓝图的核心 BindWidget 名称为 `SourceGrid`；可选绑定为 `SourceTitle`、`SourceImage`、`OperationResultText`、`CloseButton`。网格不再由 GridClass 动态创建。

## 自动化门禁

1. 编译 `ProjectXHGEditor Win64 Development`。
2. 执行 `Inventory.Container.Interaction`，应为 1 成功、0 失败。
3. 执行 `Inventory` 全套，当前基线应为 11 成功、1 成功带警告、0 失败、0 未运行。既有的权威快照旧版本过滤警告属于诊断日志，不算测试失败。

## 编辑器和运行时验收

### 资产与场景

1. 创建 `UINV_GridLayoutAsset`，例如 4×3 网格，设置唯一 `SlotId`（如 `ContainerBag`）。
2. 将测试容器蓝图继承自 `AINV_TestContainer`，设置静态网格，并把布局资产加入库存组件的 `GridLayouts`。
3. 用 `AcceptedCategory=All` 验证所有有效物品分类可放入；用 `AcceptedCategory=None` 验证所有物品都被拒绝；具体分类仍只接受匹配类别。
4. 确认输入映射 `IA_PirmaryInteract` 绑定 F 键，且测试容器的碰撞查询通道可被交互追踪命中。

### 交互链

1. 玩家进入容器 250 uu 内并对准容器，按 F。
2. 检查 `OnContainerInteractionRequested` 触发一次，目标 Actor 是当前容器，库存组件是该容器挂载的组件。
3. 对同一容器再次按 F，检查 `OnContainerInteractionClosed` 触发，活动容器和活动库存被清空。
4. 玩家移动到 250 uu 外按 F，不能产生打开请求。
5. 将 `bCanInteract` 设为 false，近距离按 F 也不能产生打开请求。
6. 容器被销毁或玩家结束游戏时，活动容器会关闭，不保留悬空组件引用。
7. 对普通拾取物按 F，原有拾取路径仍正常工作。

### 下一阶段双栏 UI

1. 打开请求创建玩家拥有的双栏界面：左侧玩家库存，右侧容器库存。
2. 从玩家栏拖入容器栏，验证整件移动、部分堆叠移动和目标合并。
3. 用 `All`、`None` 和具体分类分别验证允许与拒绝结果。
4. 拒绝、空间不足、距离失效和服务端拒绝后，两边数量、位置、朝向和占用状态保持原值。
5. 按 F、Esc、再次按 F、离开距离和容器销毁都能关闭界面并解绑目标。

## 记录方式

每次验收记录地图、容器蓝图、布局资产、AcceptedCategory、玩家到容器距离、按键结果和日志。自动化报告位于 `Saved/ContainerInteraction_2026-10-23/`。
