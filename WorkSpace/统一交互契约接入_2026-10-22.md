# 统一交互契约接入（2026-10-22）

本轮继续 #5，扩展 `FINV_InteractionContext` 的实际使用范围，并把权威 UI 的主要操作迁移到统一请求结果协议。

## 已完成

- `FINV_InteractionContext` 增加世界拾取组件、空装备槽和装备槽互换来源槽字段。
- `ProcessInventoryOperation` 新增 `Pickup`、`Equip`、`Unequip`、`Rotate` 和 `SwapEquipped` 分派。
- 新增 `BatchMove` 和 `SwapStackCounts` 类型，覆盖权威模式下的批量挤压、旋转重排和满堆数量交换。
- `TryAddItem` 改为通过统一入口提交拾取请求，服务器仍按自身容量、朝向和装备槽状态计算结果。
- 统一入口会校验非空 `Interactor` 是否对应库存拥有者或其 Pawn 的 Controller；拾取请求还会校验 `ItemComponent` 与 `TargetActor` 的归属关系，并返回 `InvalidInteractor` / `InvalidTarget`。装备相关请求会区分 `InvalidItem` 与 `EquipmentMismatch`。
- 权威模式下的网格移动、批量重排、数量交换、合并、丢弃、拆分和使用改为提交统一上下文，回执带 `RequestId`、结果状态和权威版本。
- 装备入槽、装备卸下、装备槽互换和装备槽外丢弃改为提交统一上下文。
- 旧 RPC 保留给兼容调用方和乐观模式路径，避免在预测 UI 尚未完成前改变其行为。

## 当前边界

- 乐观模式切换按用户验收意见暂缓，当前继续使用权威模式；旧的移动、合并、拆分和使用调用保留为兼容路径，#24 的预测队列与回滚尚未开始。
- 旧测试直接调用 RPC，继续用于服务端边界验证，不代表 UI 仍使用旧入口。
- 统一分派器目前对装备事务失败主要归类为通用拒绝原因，后续可细化为装备槽、回填空间和归属错误。
- `Server_MoveEquippedItem` 已有统一类型 `SwapEquipped`，跨 InventoryComponent 的转移仍属于 #19。
