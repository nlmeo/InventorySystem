# 跨容器复制注意要点

## 复制链

跨容器库存至少包含三层复制对象：容器 Actor、InventoryComponent、InventoryItem 注册复制子对象。

必须同时满足：

- 容器 Actor 设置 `bReplicates=true`；
- 容器 Actor 设置 `bReplicateUsingRegisteredSubObjectList=true`；
- InventoryComponent 使用复制和注册子对象列表；
- 新条目加入 FastArray 后调用 `AddRepSubObj`；
- `ReadyForReplication()` 中重新注册已有条目。

只复制 Actor 而不启用注册子对象列表时，服务器可以创建条目，但客户端 SourceGrid 仍然是空的。

## RPC 所有权

容器 Actor 通常没有玩家 owning connection，不能在客户端直接调用容器组件的 Server RPC。

正确路径是：

```text
客户端 UI → 玩家 PlayerController Server RPC → 服务器验证 → 服务器内部处理 InventoryComponent
```

跨容器 Transfer、容器网格移动、旋转、批量移动、合并、拆分和使用都应遵守这条规则。服务器已经通过 PlayerController RPC 获得权限后，不要再对容器 Actor 发起嵌套 Server RPC。

## 源和目标事务

一次跨容器成功事务必须同时维护源和目标：

1. 校验源条目、源 Slot、GridIndex、数量和朝向；
2. 校验目标组件、目标 Actor、目标 Slot、Index 和分类；
3. 创建目标条目或合并目标堆叠；
4. 成功后移除或扣减源条目；
5. 更新源和目标的权威 Revision；
6. 让源和目标都进入客户端刷新/复制流程。

目标创建失败时，源库存不能提前扣减。

## 回执与复制时序

操作回执可能早于 FastArray 条目复制到达客户端。回执只证明服务器已完成操作，不能证明目标条目已经能被客户端网格使用。

- 回执负责确认结果和版本；
- FastArray 的 `PostReplicatedAdd` / `PreReplicatedRemove` 负责条目到达和移除；
- 网格应监听复制事件并按客户端当前库存重铺；
- 不要用重复拖放或周期性刷新掩盖复制缺失。

服务器远程模式必须调用真正的 `Client_InventoryOperationCompleted(...)` RPC。直接调用 `_Implementation` 只会修改服务器对象；Standalone 才可以直接调用实现体。

## RequestId

客户端普通操作和服务器内部容器转发不能共用同一组 RequestId。否则新请求可能命中 `CompletedOperations` 中的旧编号，被当作重放请求：日志看起来是 `Failure=0`，但没有新的事务处理。

建议使用两个命名空间：客户端低位递增 ID，服务器内部容器请求使用独立高位 ID。看到 `Failure=0` 时，必须确认同一个 RequestId 有新的“开始处理”和“处理完成”记录。

## 落点和旋转

鼠标事件的 `GridIndex` 不是最终左上角落点。跨容器提交前必须重新执行最终空间查询，并使用最终 `ItemDropIndex`、Slot 和 Payload 旋转状态；服务器仍需再次校验边界和占用。

拖拽中可能同时存在物品持久化朝向、源网格临时 Payload 朝向、Slate 操作 Payload 朝向。自动旋转或手动 `R` 后，参与预览、拖拽图标和提交的 Payload 必须同步。

## 日志排查顺序

1. `提交拖放`：确认目标 Slot、Index、Rotated；
2. `客户端发送请求`：确认经过 PlayerController；
3. `服务器内部提交`：确认 RequestId 属于服务器命名空间；
4. `开始处理`：确认没有旧结果重放；
5. `处理完成`：确认 Failure、Changed、Items、Revision；
6. 检查 SourceItems、Source 是否仍含 Item、TargetItems；
7. 检查 FastArray 条目是否到达客户端；
8. 检查 SourceGrid 是否在复制回调后重铺。

只有同时看到新的 RequestId、服务器开始处理、服务器处理完成和源/目标状态变化，才能判定跨容器事务真正完成。

## 新来源类型接入清单

掉落包、弹挂、尸体和储物箱接入时，确认 Actor 复制、注册子对象复制、InventoryComponent 复制、条目注册、服务器访问策略、Session 来源网格绑定、关闭时拖拽清理和复制到达后的 SourceGrid 重铺全部完成。
