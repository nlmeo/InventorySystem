# 跨容器库存迭代归档

日期：2026-10-26
项目：ProjectXHG

## 一、当前架构约定

- `UINV_InventorySessionWidget` 是玩家背包和容器 UI 的统一会话根节点。
- 玩家控制器持有并管理 Session，`I` 键只切换 Session 中玩家背包子 UI 的可见性。
- 容器相关客户端请求统一通过 `AINV_PlayerController` 转发到服务器。
- 容器组件不直接发送需要 owning connection 的客户端 RPC。
- `UINV_InventoryItem` 是复制子对象，跨容器整件转移时复用原条目并切换宿主。
- 跨容器高亮和交换规划由客户端负责，服务器负责验证客户端提交的计划参数。

## 二、已完成的主要功能

### UI 与 Session

- Session 作为背包和其他 UI 的唯一连接纽带。
- 移除 `UINV_SpatialInventory::RebindInventoryForSession()` 及相关重复绑定路径。
- 玩家背包、容器网格通过 Session 管理和刷新。

### 跨容器转移

- 玩家背包与容器之间的拖拽转移。
- 容器物品拖出窗口丢弃。
- 容器物品拖到角色装备槽。
- 容器装备替换角色已有装备。
- 双击快速转移。
- 跨容器旋转物品转移。
- 跨容器多物品区域交换。
- 目标区域左上角为空时仍可交换。
- 混合分类物品回填到玩家其他分类网格。
- 多个回填物品之间的占用冲突检测。
- 药品等 1x2 物品旋转为 2x1 后批量回填。

### 网络与复制

- 容器请求通过 PlayerController RPC 转发。
- 服务端请求使用高位 RequestId，避免被旧 CompletedOperations 误判为重复请求。
- `DeliverOperationResult` 已区分真实 Client RPC 和 Standalone 实现。
- 容器组件支持注册已有复制子对象。
- 跨容器整件转移复用原 `UINV_InventoryItem`，执行：
  1. 源 FastArray 移除；
  2. 源复制子对象注销；
  3. Rename 到目标宿主；
  4. 更新 ContainerId / GridIndex / OwningInventory；
  5. 加入目标 FastArray；
  6. 注册到目标复制子对象列表。

### 交换与回滚

- 普通跨容器交换支持多个覆盖物品。
- 不同分类物品可回填到其他网格。
- 客户端提交 `FINV_CrossContainerSwapEntry` 计划。
- 服务器按物品对象指针匹配客户端计划，避免 TMap 和 InventoryList 顺序不同造成药品/装备目标网格互换。
- 服务器拒绝缺少客户端批量计划的跨容器非堆叠交换。
- 换宿主失败时恢复源列表和复制注册关系。
- 换装第二个条目失败时恢复拖拽物品原容器、位置、旋转和装备标签。

### 装备事件

- 容器装备换装现在通过统一装备事件入口。
- 已处理 `bEquipable` 从源 Manifest 错误复制导致 `OnEquip()` 提前返回的问题。
- 增加装备复制时序兜底。
- 统一 `BroadcastEquipmentEvent()` 处理装备/卸下事件。
- 装备槽互换保持先卸下再装备的顺序。

### 失败反馈

- 统一容器失败结果显示。
- 已覆盖请求无效、请求过期、交互者无效、目标无效、空间不足、位置无效、分类不匹配、装备槽不匹配、目标占用、生成失败等提示。
- 失败后清理容器网格、玩家网格、悬持物品和高亮状态。

## 四、最近一次关键修复

服务器和客户端对跨容器覆盖物品的排列顺序不同：

- 客户端计划来自 `SpaceItemsMap`；
- 服务器目标物品来自 `InventoryList`；
- 不能按数组下标套用计划；
- 当前已改为按 `UINV_InventoryItem*` 对象指针匹配计划。

另一个关键修复是客户端高亮规划记录已规划占用区域，避免两个药品同时判断为可以放入同一个唯一空位。
