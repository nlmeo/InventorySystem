# ProjectXHG Inventory 1.0 收尾清单

日期：2026-10-27
目标：冻结现有功能，整理为可验收、可交接、可回退的 1.0 版本。

## 一、功能冻结

- 不再新增库存交互功能。
- 不改变 Session、PlayerController 转发、跨容器事务和复制子对象换宿主架构。
- 新发现问题只允许修复现有功能，不扩展交互范围。
- 所有修复都必须重新编译并更新验收记录。

## 二、代码整理

### InventoryComponent

- 抽取跨容器规划和服务器校验中的重复逻辑。
- 保留跨容器整件条目复用，不恢复创建副本的旧路径。
- 清理已经禁用的旧单目标跨容器交换回退逻辑。
- 检查 `SecondaryItem` 仅用于堆叠合并时的兼容路径。
- 统一复制子对象换宿主、FastArray 移除/加入和失败回滚流程。
- 检查装备事件入口，确保 `OnEquip` / `OnUnequip` 不重复触发。

### InventoryGrid / UI

- 让高亮规划和拖放提交继续使用同一套客户端交换计划。
- 清理调试屏幕提示、临时日志和重复刷新入口。
- 检查失败后拖拽状态清理是否覆盖玩家网格、容器网格和装备槽。
- 保留必要的服务器失败日志，减少重复日志。

### PlayerController / RPC

- 保证所有容器客户端请求均通过 PlayerController 转发。
- 清理不再使用的旧容器 RPC 调用路径。
- 检查失败结果、刷新和 Session UI 反馈顺序。

## 三、1.0 验收固化

### 普通操作

- 玩家背包内部移动、旋转、堆叠、拆分、合并。
- 容器内部移动、旋转、堆叠、拆分、合并。
- 容器物品拖出丢弃。
- 快速转移。

### 跨容器操作

- 单物品转移。
- 多物品区域交换。
- 左上角为空的区域交换。
- 混合分类回填其他网格。
- 多物品旋转回填。
- 目标网格空间不足。
- 目标分类不匹配。
- 客户端计划顺序与服务器 InventoryList 顺序不同。
- 重复提交和失败回滚。

### 装备操作

- 容器装备到空装备槽。
- 容器装备替换已有装备。
- 玩家装备与容器交换。
- 装备效果只触发一次。
- 卸下效果只触发一次。
- 装备 Actor 不重复生成、不残留。

### 网络操作

- 监听服务器。
- 专用服务器。
- 两个客户端观察同一容器。
- 断开并重新连接。
- 关闭并重新打开 Session。
- 服务器拒绝请求后的状态恢复。

## 四、日志和错误反馈

保留以下关键日志：

```text
[Inventory][Transfer] 客户端发送请求
[Inventory][Operation] 开始处理
[Inventory][Transfer] 复制子对象换宿主
[Inventory][Operation] 处理完成
[Inventory][Transfer] 服务端操作结果
```

确认失败结果均能显示明确原因：

- 空间不足；
- 分类不匹配；
- 位置无效；
- 容器拒绝交互；
- 装备槽不匹配；
- 请求无效或过期；
- 生成物品失败。

## 五、版本整理

- 更新项目版本号为 `1.0.0`。
- 保存一次完整的编译产物。
- 保存最终配置和布局资产清单。
- 生成最终验收记录。
- 记录当前已知限制。
- 创建 1.0 版本标签或归档分支。
- 保留 1.0 前最后一次可回退快照。

## 六、1.0 版本禁止事项

- 不新增新的容器类型。
- 不新增新的交换规则。
- 不重新设计 Session 架构。
- 不恢复 `RebindInventoryForSession()`。
- 不重新引入跨容器客户端重试机制。
- 不在没有回归测试的情况下修改已通过的跨容器路径。

## 七、建议执行顺序

1. 代码清理和重复逻辑收拢。
2. 完整编译。
3. 专用服务器和双客户端回归。
4. 更新验收文档。
5. 生成 1.0 版本快照和压缩包。
6. 冻结功能。
