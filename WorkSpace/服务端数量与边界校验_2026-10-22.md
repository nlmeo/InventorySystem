## 改动

- 合并必须为两个不同的本库存堆叠条目，当前数量合法且类型一致；请求数量不得超过源数量或目标剩余容量。超容量整笔拒绝，不静默截断。用剩余容量比较避免加法溢出。
- 数量交换检查双方当前数量及交换后容量。拾取填充跳过数量或上限异常的已有堆叠。
- 使用物品只接受一次一件（`StackCount == 1`），要求 Consumable 分类与 ConsumableFragment；拒绝零数、负数、批量请求及非消耗品，校验位于扣数和 OnConsume 之前。当前 UI 本来就一次使用一件；批量使用需另行明确效果次数与事务语义。
- 堆叠丢弃要求 `0 < 请求数量 <= 当前数量`；非堆叠物品以物理件数 1 发起，内部计数仍保留原来的 0，网格发起端同步调整。直接丢弃仍在装备中的物品被拒，避免绕过卸下处理。
- 拆分先检查数量、库存归属及源容器/索引，再搜索落点；不再信任请求改写源位置。失败不改变源数量、位置或朝向，合法拆分保留双朝向搜索。
- 未配置的容器、非 Grid 面板、非法尺寸及超过 int32 范围的容量均拒绝。区域检查拒绝非正物品尺寸，用减法比较防止尺寸相加溢出；批量移动拒绝重复物品。
- 装备入口补齐分类、EquipmentFragment、自换、外部库存条目和第三件装备占槽检查；装备槽之间移动也补齐物品类型与第三方占槽检查。合法替换仍沿用现有流程，未将多 RPC 链改为事务。

## 剩余边界

- 装备 UI 仍提前改写 EquippedSlotType，部分网格落位会清除此字段；本机 UI 与服务器共用对象。来源装备槽、被换下物品是否确为当前占用者、空槽及重复请求的可靠判断，需要 #4.2/#4.3/#4.4 的回执、事务及确认态隔离。基础占槽检查不能替代这些工作。
- 服务器尚无独立装备槽配置集合，请求携带的槽标签不代表服务器已确认该槽存在；后续应由资产提供允许槽集合。
- 普通移动/交换的来源状态尚未全面收紧；目标面板分类与标签规则未在所有路径统一。需结合 UI 临时态隔离及统一交互契约补齐。
- 代码核查另发现：合法丢弃仍先移除/扣数再尝试 SpawnPickupActor，控制器、Pawn、掉落类无效或生成失败时缺少生成结果及恢复机制。属于既有风险，尚未专项复现，已登记待办。
- 未做真实网络延迟/丢包验证，以及实际属性系统或世界掉落生成失败注入。非法请求在代码中先校验再进入效果/生成调用，当前自动化主要断言库存状态及条目变化。
