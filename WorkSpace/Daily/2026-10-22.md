# 2026-10-22 工作记录

## 今日目标

继续处理 Inventory 系统的装备事务、服务器权威 UI 和快速换装问题，完成编译验证并进行实际游戏回归。

## 完成内容

### 1. 装备原子事务与尺寸回填

- 新增并接入 `Server_EquipTransaction`，将装备、卸下和回填合并为一次服务器事务。
- 快速换装时，优先尝试原网格位置；尺寸不匹配时搜索当前网格的其它位置，并尝试旋转。
- 被换下装备没有可用空间时直接取消操作，保持原装备和原网格状态。
- 服务器快速卸下不再信任客户端缓存的回填索引，由服务器根据自己的占用表重新选择位置和朝向。
- 修复装备槽卸下后重复发送 `Server_MoveItem` 的问题，消除 `来源 Equippables[-1]` 再次写入已占用格的错误日志。

### 2. 服务器权威 UI 第一批

- 直接移动、普通交换、批量挤压和旋转重排在权威模式下先提交服务器，再按权威状态刷新。
- 权威重铺遇到没有服务器确认索引的条目时不再自动找空位并回报服务器，避免被拒绝的装备被伪造成第二次回填。
- 右键菜单丢弃在权威模式下不再先 `PickUp` 清空本地容器和索引，直接提交原状态给服务器。
- 快速换装在本地表现修改前提交事务，并显式传递目标装备槽；拒绝后主动请求权威刷新。

### 3. 装备槽和快速卸下修复

- 修复装备槽 UI 使用 `MatchesTagExact` 导致服务器已装备成功、UI 却没有创建可双击图标的问题，统一使用标签层级匹配。
- 修复卸下事务中 `ItemToEquip == nullptr` 时错误查找第一个空装备槽的问题，避免把 `Cloaks` 错传成 `Masks`。
- 增加双击快速卸下后的短暂同物品重入保护，避免新建背包图标收到同一轮双击后立即再次快速装备。
- `SlottedItems` 由按索引清理改为按物品身份清理旧映射，避免装备、旋转和尺寸变化后留下过期索引。

### 4. 日志和问题定位

- 分析了 `aqProf.dll`、`VtuneApi.dll` 缺失日志，确认它们是可选性能分析组件警告，与装备逻辑和编译无关。
- 根据权威快照 `纠正=1` 和 `MoveItem 被拒` 日志，定位了客户端临时落位、服务器回填和重复 RPC 的状态不一致问题。
- 增加装备事务拒绝日志，输出当前装备槽标签、请求槽标签和装备状态，便于后续联机问题定位。
