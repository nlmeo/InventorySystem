# 双栏容器完整测试流程（2026-10-23）

本流程用于本轮 #19 第二阶段验收。目标是确认测试容器由网格资产驱动，容器 Actor 挂载库存组件，玩家按 F 打开双栏界面，跨组件转移由服务器裁决，拒绝后两边状态恢复一致。

## 0. 自动化门禁

先保存工程并关闭可能占用模块的编辑器窗口，然后执行 ProjectXHGEditor Win64 Development 编译。应看到 Result: Succeeded。

随后执行 Inventory 全套自动化，报告目录为 Saved/ContainerInteraction_2026-10-23/FinalRegression。基线为 11 成功、1 成功带既有权威快照诊断警告、0 失败、0 未运行。Inventory.Container.Interaction 单独应为 1 成功、0 失败。

## 1. 测试资产和场景

1. 创建一个 4×3 或更大的 UINV_GridLayoutAsset。
2. 给玩家背包和容器各配置至少一个唯一的 Grid 面板 SlotId，设置正数行列和 TileSize。
3. 为容器面板准备三份测试配置：AcceptedCategory=All、AcceptedCategory=None、一个具体分类。
4. 创建继承 AINV_TestContainer 的蓝图，设置静态网格、查询碰撞和库存布局资产。
5. 将容器库存组件设置为 bAllowTransfer=true、bRequireContainerOpenForTransfer=true、TransferInteractionDistance=250。
6. 在玩家控制器默认值中设置 ContainerInventoryWidgetClass 为容器 UI 蓝图；蓝图继承 UINV_ContainerInventoryWidget，使用 OnContainerOpened 显示左右栏，使用 OnOperationResult 显示失败原因。
7. 确认 IA_PirmaryInteract 绑定 F，背包开关仍使用原 Toggle 输入。

容器来源 UI 蓝图必须添加一个继承自 UINV_InventoryGrid 的控件，并命名为 SourceGrid；它会自动绑定容器 InventoryComponent 和首个 Grid 面板。可选控件名称为 SourceTitle、SourceImage、OperationResultText、CloseButton。缺少 SourceGrid 时只告警并取消来源 UI 初始化。CloseButton 点击和 Esc 都会关闭容器会话。玩家侧 SpatiallyInventory 由组合根单独承载。

## 2. 打开和关闭

1. PIE 后将玩家放到容器 250 uu 内，对准容器按 F。
2. 确认容器高亮和交互请求出现；双栏界面显示玩家网格和容器网格。
3. 确认左栏物品来自玩家库存，右栏物品来自容器库存，两个网格尺寸来自各自资产面板。
4. 再次对准同一容器按 F，确认界面关闭、鼠标隐藏、输入回到游戏模式。
5. 按 Esc 或绑定的关闭键，确认同样关闭。
6. 打开后移动到 250 uu 外，确认界面自动关闭，容器打开状态同步为 false。
7. 打开后销毁容器 Actor，确认界面关闭且不再访问已销毁库存组件。

## 3. 跨容器转移

1. 从玩家栏拖一件普通物品到容器空格，确认服务器成功后源栏移除、目标栏出现，数量守恒。
2. 从容器栏拖一件普通物品回玩家栏，确认反向转移成功。
3. 对可堆叠物品按住 Shift 拖动，确认只转移 1 件，源数量减少 1，目标数量增加 1。
4. 将同类型堆叠拖到目标堆叠，确认按容量合并；目标满时只转移可容纳数量，不能超过最大堆叠。
5. 放置可旋转物品，分别测试原朝向和按 R 后旋转朝向，确认服务器保存最终朝向。
6. 放置多格物品到边缘、角落和不足空间位置，确认预览、服务器校验和最终显示一致。

## 4. AcceptedCategory

1. All：放入有效分类物品应成功。
2. None：任何物品都应拒绝，源数量、目标数量和位置都不改变。
3. 具体分类：匹配分类成功，不匹配分类拒绝。
4. 拒绝后重新拖回原栏，确认源条目仍存在，图标、数量、朝向和占用格恢复。

## 5. 拒绝和边界

逐项执行，每项失败后检查两边数量总和、条目身份、容器 ID、GridIndex、朝向和 UI 图标：

1. 容器 bAllowTransfer=false。
2. 容器 bRequireContainerOpenForTransfer=true 但玩家未打开容器。
3. 玩家离开 250 uu 后拖放。
4. 目标没有足够空间。
5. 目标分类不接受物品。
6. 数量输入为 0、负数或超过源堆叠数量。
7. 源条目已经被移除后重复拖放。
8. 重复发送同一个请求，确认不会重复扣除或重复生成。

## 6. 回归项

1. 普通物品按 F 仍能拾取。
2. I 或原背包键仍能独立打开和关闭玩家背包。
3. 装备槽拖入、卸下、交换和装备外拖丢弃不受影响。
4. 旋转、拆分、合并、批量移动、掉落生成失败保护继续通过。
5. 关闭容器后重新打开，左右两栏都按最新权威状态重铺。

## 7. 记录结果

记录地图、客户端数量、容器蓝图、布局资产、AcceptedCategory、距离、操作步骤、LogTemp 关键日志和最终状态。
